# Changelog

## Unreleased

- Initial project scaffold and Claude Code settings.
- Add `main.py` as a quick Python entry point to test the setup.
- Add `README.md` pointing to the GitHub repo.
- Add a local Postgres setup via `pg0-embedded` (`scripts/run_db.py` / `scripts/stop_db.py`, `requirements.txt`) — no existing DB was found on the machine, so this runs a self-contained, no-install/no-Docker Postgres for local dev, replaceable with a production DB later.
- Remove the placeholder `main.py` and restructure the repo into a monorepo: `backend/` (FastAPI skeleton with `/api/v1/health` + `/api/v1/health/db`, SQLAlchemy session, Alembic wired up, pytest) and `frontend/` (Next.js app-router skeleton with a placeholder public lead form and an auth-TODO'd internal leads list, both scaffolded with TypeScript + Tailwind). Verified end-to-end: backend tests pass against the real local Postgres, `next build`/`lint` pass, and the frontend's home page live-fetches backend `/health` successfully. Added `.github/workflows/ci.yml` (backend lint+test, frontend lint+build) and per-app READMEs. Installed Node.js LTS via winget (wasn't present on the machine).
- Rewrite the root `README.md` with a single "Run the whole app locally" quickstart (DB → backend → frontend, three terminals) so the full stack can be started end-to-end, including a note about the port-8000 conflict this dev machine has.
- Make port 8010 the documented default backend port (instead of uvicorn's built-in 8000) to avoid the common 8000 conflict going forward. Updated `frontend/src/lib/api-client.ts`'s fallback, `frontend/.env.local.example`, and the root/backend/frontend READMEs to match.
- Fix `ruff check` failures in the backend: sort/merge imports in `alembic/env.py` (I001), and move `health_db`'s `Depends(get_db)` out of the argument default into a module-level `DbSession = Annotated[...]` alias (B008).
- Add the Lead feature: `Lead`/`LeadResume` SQLAlchemy models + Alembic migration, `POST/GET /api/v1/leads`, `POST /api/v1/leads/{id}/reach-out`, `GET /api/v1/leads/{id}/resume`. Resume files are stored in Postgres (not the filesystem) behind a `StorageBackend` interface so a future switch to S3 is one class + a setting flip. Centralized `DbSession` in `app/api/deps.py` (health.py now imports it instead of defining its own copy). Email sending and real auth remain out of scope (stubbed/TODO). Verified end-to-end against the real local Postgres: 10 pytest tests pass, and a full manual curl pass (create → download → reach-out → 409-on-repeat → 404-on-unknown) confirmed correct behavior.
- Fix: the public lead form's submit button did nothing (`handleSubmit` only called `preventDefault()` — a known gap, not yet wired since the backend endpoint didn't exist at the time). Wired it to the real `POST /api/v1/leads` via a new `createLead()` in `api-client.ts`, with loading/success/error UI states. Also wired the internal leads list to the real `GET /api/v1/leads` (table with name, email, resume link, state, submitted date) so submissions are actually visible — it was still showing a static "No leads yet" placeholder. Auth and the "mark reached out" button remain unwired.
- Add `DECISIONS.md`: a topical reference for key decisions/tradeoffs and real bugs found and fixed across the build so far, distilled out of `CONVERSATION_LOG.md`'s chronological narrative. Added a matching convention note to `CLAUDE.md`.
- Allow `.txt` resumes in addition to PDF/DOC/DOCX (`Settings.resume_allowed_content_types`); added a matching `accept` attribute on the frontend's file input and a backend test locking in the new type.
- Redesign the internal leads table (`frontend/src/app/internal/leads/page.tsx`): bordered/rounded container, muted header row, row dividers, hover states, and colored pill badges for lead state (amber "Pending" / green "Reached out") — was a bare unstyled `<table>` that looked cluttered. Verified visually with Playwright (installed ad hoc for this, not a project dependency) since `chromium-cli` wasn't available in this environment.
- Strengthen resume-download test coverage: the existing byte-round-trip test now also asserts `Content-Type`/`Content-Disposition` headers, added a matching round-trip test for `.txt`, and a 404-on-unknown-id test for the download endpoint (previously only the reach-out endpoint had one).
